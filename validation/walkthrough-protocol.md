# Walkthrough Protocol Update

Date: 2026-10-23. Scope: instructions, report template and public documentation. No major benchmark, human study or real application audit was run.

## Implemented

- First-encounter observations precede authorized diagnosis; prior solution exposure is disclosed.
- Evidence modality, completion and assistance remain separate. Accessibility-tree success does not establish visual discoverability.
- Consequential ambiguous actions can have brief, contemporaneous expectation/outcome notes; predictions are not reconstructed after the fact.
- Task-relevant conditions and a journey/state map replace demographic roleplay and exhaustive default audits.
- Meaningful completion includes relevant persistence, return, correction and recovery checks within authorization.
- Replayable findings and recommendations retain safeguards, tradeoffs, acceptance tests and disconfirming evidence.

## Limited Assumption Check

Four authored synthetic multiple-choice evidence packets were evaluated during development. Expected interpretations were written before submission. The selected interpretation agreed with the author in all four packets:

| Packet | Supported Interpretation |
| --- | --- |
| Export completed using an accessible name; icon tooltip only known from source | Completion in the tested modality; visual discoverability untested. |
| Continue creates a reversible draft and opens the promised review step | Draft persistence does not establish final submission; the proposed relabeling is unsupported. |
| Fresh browser session after the reviewer learned the route from source | Prior knowledge remains; report completion without claiming a clean first encounter or inventing a defect. |
| Required bulk-edit confirmation works; separate export remains queued | Preserve the safeguard and keep export completion uncertain; neither extra actions nor an observation timeout proves a defect. |

These were judgment probes of protocol assumptions, not executions of Longshot against a rendered app. The author wrote the alternatives and expected answers; no blinded human adjudication, independent sample, repeated-run variance estimate or improvement measurement was performed. Agreement is a consistency check, not human ground truth or a reliability score. No new behavioral rule was justified solely by that agreement.

## Package and Presentation Checks

The skill-creator structural validator passed for the repository and installed skill using an existing local YAML package. Installed skill files matched repository bytes, and local skill/documentation links resolved. Markdown and HTML heading audits passed (12 README headings, 28 page headings). Focused Chrome checks inspected the existing page design with the new protocol content at desktop and narrow widths; anchors resolved, the local font loaded and no page-level horizontal overflow was measured. These checks do not establish broad accessibility or skill effectiveness.

Human-grounded evaluation remains [a proposed research plan](human-grounded-plan.md). Future tests should assess issue quality and recommendation value rather than treating these four packets as four usability studies.
